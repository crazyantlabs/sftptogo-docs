The SFTP To Go Management API authenticates requests with an API key, sent as a bearer token in the `Authorization` header. A request with a missing or incorrect key returns `401`. A request with a valid key that the API doesn't allow, such as one that would go over your plan's credentials limit, returns `403`. Send every request over HTTPS.

<Tabs groupId="code-samples">
<TabItem value="curl" label="curl">

```bash title="Using an API key"
curl "https://api.sftptogo.com/organizations/$SFTPTOGO_ORGANIZATION_ID/users" \
  -H "Authorization: Bearer $SFTPTOGO_API_KEY"
```

```javascript title="Using an API key"
const response = await fetch(
  `https://api.sftptogo.com/organizations/${process.env.SFTPTOGO_ORGANIZATION_ID}/users`,
  { headers: { Authorization: `Bearer ${process.env.SFTPTOGO_API_KEY}` } },

const credentials = await response.json();
```

import os
import requests

response = requests.get(

To get an API key, ask our support team through the in-app chat.

## Organization scope

A key belongs to one organization. Every path starts with that organization's ID: the ID that follows `/organizations/` in your dashboard's address.

A key reaches only its own organization, and only organization endpoints. It can't reach account-level endpoints, such as your account's settings. Requests outside that scope return `401`, and so does every request while your organization isn't active.

## Secure your API keys

A key has full access to its organization: anyone who has it can read the password of every set of credentials, and create, change or delete them. There are no read-only or limited keys.

* Keep keys on your servers. Never put one in browser code, a mobile app, a repository, a log, a URL or a query string.
* Load the key from an environment variable or a secret manager, as the examples above do.
* Never paste a key into an AI assistant, including the ones in the **Explore with AI** menu on these pages.
* If a key leaks, or might have, contact our support team through the in-app chat at once to have it revoked.

## Authentication errors

A request that can't be authenticated returns `401 Unauthorized` with this body. It doesn't say which check failed: check the header, the key, and the organization in the path. For every other error, see [Errors](./errors.md).

```json
{
  "message": "Unauthorized"
}
```

## Revoke a key

Keys don't expire. To revoke one, contact our support team through the in-app chat. Requests made with a revoked key return `401`.

To replace a key without interrupting your integrations, ask for the new key first, switch over, then have the old one revoked.

## Try it

Each operation page has a request panel. Paste your API key into its **Bearer Token** field and click **Send API Request**. The key stays on that page only: it isn't saved, and it's gone when you leave.

Requests from the panel run against your live organization with your key's full access, and a request that creates, changes or deletes something does so for real. Responses can show passwords in clear text, so don't use the panel on a shared or untrusted computer.
